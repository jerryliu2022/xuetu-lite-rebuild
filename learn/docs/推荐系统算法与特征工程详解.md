## 0. 全局视角：一次推荐请求发生了什么

用户在页面点开「专业路径」，浏览器请求：

```
GET /api/recommendations/professional?student_id=YY08&filter=all
```

这个请求最终落到 `backend/recommender.py` 的 `recommend_professional()`（`:250-296`）。整个链路是：

```
① 加载模型     load_model()              读 data/artifacts/ranker_model.json (995 KB)
② 取学生       SELECT * FROM student     拿到 major / semester
③ 算黑白名单   _touched_video_ids()      哪些视频"碰过"了
④ 混召         professional_candidates() 44,997 条资源 → 114 个候选  ← 召回
⑤ 抽特征       feature_vector()          每个候选变成 8 个数字
⑥ 打分         score()                   逻辑回归 → 点击概率
⑦ 混合         blended_score             模型分 + 规则分 + 质量分
⑧ 重排         mmr_rerank()              打散同质内容 → 24 条        ← 重排
```

关键：**第 ④ 步只负责"捞得全"，第 ⑥⑧ 步才负责"排得准"**。

对应代码（`:250-296`，节选）：

```python
def recommend_professional(
    student_id: str,
    filt: str = "all",
    model_override: Dict[str, Any] | None = None,
    exclude_video_ids: Set[str] | None = None,
    context_video_ids: Set[str] | None = None,
) -> List[Dict[str, Any]]:
    con = connect()
    model = model_override or load_model()                    # ① 加载模型
    student = rows(con, "SELECT * FROM student WHERE student_id=?", (student_id,))[0]  # ②
    touched = _touched_video_ids(con, student_id, exclude_video_ids)   # ③
    context = _touched_video_ids(con, student_id, context_video_ids)   # ③
    reasons = professional_candidates(                        # ④ 召回
        con, student, model,
        exclude_video_ids=touched,
        context_video_ids=context,
    )
    done_videos = touched
    history = sorted(context)
    scored = []
    for video_id, reason in reasons.items():
        video = rows(con, "SELECT * FROM video WHERE video_id=?", (video_id,))[0]
        ...
        features = feature_vector(con, student, video, reasons, model, history=history)  # ⑤
        predicted_ctr = score(features, model)                # ⑥
        blended_score = (                                     # ⑦
            0.62 * predicted_ctr
            + 0.2 * recall_strength(reason)
            + 0.12 * freshness_bonus(video)
            + ...
        )
    return mmr_rerank(sorted(scored, key=..., reverse=True), model, 9)   # ⑧
```

## 1. 为什么是「两段式」推荐

### 1.1 问题定义

项目里有 **44,997 条课程资源**，要给某学生挑出**最该看的 24 个**（一屏 4 列 × 6 行）。

理论上可以让排序模型对全部 44,997 条逐个打分再排序。但真实推荐系统不会这么做，原因有两个：

1. **算力**：工业级场景候选池是百万级，逐个精排跑不动。
2. **特征成本**：有些特征算起来很贵（比如 ItemCF 相似度要遍历历史 × 相似表），只有少量候选才负担得起。

所以标准做法是两层漏斗：

| 阶段 | 别名 | 职责 | 本项目规模 |
|---|---|---|---|
| 召回（Recall） | 粗筛 | 用便宜规则把相关的捞出来，**宁可错捞，不可漏掉** | 44,997 → 114 |
| 排序（Ranking） | 精排 | 用模型给候选排序，**追求头部准确** | 114 → 24 |
| 重排（Re-rank） | 打散 | 调整结果构成，避免同质化 | 24 → 24 |

### 1.2 本项目选型

`train_model.py:302` 里官方声明了自己的技术选择：

```python
"choice": "Hybrid recall + TF-IDF ItemCF + lightweight logistic ranker; "
          "CPU-only, no heavy GPU/vector DB dependency."
```

翻译一下：**混合召回 + TF-IDF 协同过滤 + 轻量逻辑回归排序，纯 CPU 跑，不依赖 GPU 和向量数据库。**

这是一个刻意做"轻"的工程选择——竞赛项目要在普通笔记本上跑起来，而且所有算法都要能讲清楚，不能是黑盒。

## 2. 召回阶段：5 路混合召回

核心函数：`backend/recommender.py:67-126` 的 `professional_candidates()`。

"混合召回"的意思是：**用 5 种不同思路各捞一批，合并去重**。之所以要 5 路，是因为单一路径都会漏：

- 只用图谱 → 漏掉跨专业课
- 只用协同 → 冷启动学生没历史就废了
- 只用热度 → 推的全是爆款，毫无个性

### 2.1 三条课程图谱规则

图谱数据来自 `course` 表的 `prerequisites` 字段（逗号分隔的先修课 ID 串）。

```python
# recommender.py:77-79  先查三种课程状态
studying  = rows(con, "SELECT * FROM course WHERE status='studying'")
completed = rows(con, "SELECT * FROM course WHERE status='completed'")
planned   = rows(con, "SELECT * FROM course WHERE semester=?", (student["semester"] + 1,))
```

**规则 1（`:80-83`）：正在学 → 同课**

```python
for course in studying:
    for video in rows(con, "SELECT video_id FROM video WHERE course_id=?", (course["course_id"],)):
        if video["video_id"] not in touched:
            reasons.setdefault(video["video_id"], f"正在学习《{course['name']}》，召回同主题视频")
```

含义：你正在上《数据结构》，那就推荐《数据结构》下所有视频。**配合课堂进度，需求最急。**

**规则 2（`:84-88`）：学过 → 后继**

```python
for done in completed:
    for next_course in rows(con, "SELECT * FROM course WHERE prerequisites LIKE ?", (f"%{done['course_id']}%",)):
        for video in rows(con, "SELECT video_id FROM video WHERE course_id=?", (next_course["course_id"],)):
            if video["video_id"] not in touched:
                reasons.setdefault(video["video_id"], f"已学《{done['name']}》，推荐后继进阶课")
```

含义：你学完《线性代数》(C102)，就去找**先修要求里含 C102** 的课——查出来是 C502《机器学习》。**知识是阶梯，学完基础才能学进阶。**

⚠️ 这里是字符串模糊匹配 `LIKE '%C102%'`，不是精确匹配。当前课程 ID 都是 4 位不会误伤，但属于脆弱写法（见第 9 节）。

**规则 3（`:89-92`）：下学期 → 预习**

```python
for course in planned:
    for video in rows(con, "SELECT video_id FROM video WHERE course_id=?", (course["course_id"],)):
        if video["video_id"] not in touched:
            reasons.setdefault(video["video_id"], f"下学期将学《{course['name']}》，适合假期预习")
```

含义：学生 `semester=3`，下学期就是第 4 学期，把第 4 学期的课（操作系统、计算机网络）先推荐出来预习。

### 2.2 ItemCF 协同召回（`:93-96`）

```python
for watched_id in context:
    for item in model["item_similarity"].get(watched_id, [])[:4]:
        if item["video_id"] not in touched:
            reasons.setdefault(item["video_id"], "基于你的学习记录做 ItemCF 相似召回")
```

`model["item_similarity"]` 是**离线算好**的"视频-视频"相似度表，存在模型 JSON 里。

- `context` = 这个学生看过（进度 > 0）的视频 ID 集合
- 对着每个看过的视频，查它最相似的 top4
- 思路是"看过 A 的人，多半也会喜欢和 A 像的 B"

这套相似度是**基于文本内容**算的（不是行为共现），算法在 `train_model.py:31-69`，详见第 3.5 节。

### 2.3 专业方向召回（`:97-103`）

```python
for video in rows(con, "SELECT video_id FROM video WHERE major=? ORDER BY popularity DESC LIMIT 16",
                  (student["major"],)):
    if video["video_id"] not in touched:
        reasons.setdefault(video["video_id"], f"匹配{student['major']}专业方向，优先补齐核心课程")
```

直接按 `video.major` 精确匹配学生的专业，取热度前 16。**保底手段**：就算图谱和协同都没捞到东西，专业相关的总能捞一批。

### 2.4 专业不匹配剔除（`:104-113`）

```python
incompatible = rows(con, """
    SELECT DISTINCT video_id FROM video
    WHERE major IS NOT NULL AND major<>?
""", (student["major"],))
for item in incompatible:
    reasons.pop(item["video_id"], None)
```

**这是"负召回"**：凡是标了专业、且专业不是这个学生的，直接从候选里删掉。比如给"计算机科学与技术"的学生，不会推荐"护理学"的视频。

### 2.5 热门兜底（`:114-125`）

```python
for video in rows(con, """
    SELECT video_id FROM video
    WHERE major=? OR major IS NULL OR major=''
    ORDER BY popularity DESC
    LIMIT 10
""", (student["major"],)):
    if video["video_id"] not in touched:
        reasons.setdefault(video["video_id"], "热门优质课程兜底召回")
```

最后再补 10 个热门（专业匹配或无专业标注的）。**保证候选池永远填得满**，不会因为前 4 路都没命中而返回空列表。

### 2.6 实测召回结果

以学生 `YY08`（郑好，大二，semester=3，计算机科学与技术）为例，实跑得到 **114 个候选**：

| 召回路径 | 候选数 | 占比 |
|---|---|---|
| 路 1 正在学 → 同课（数据结构与算法 7 + 概率论与数理统计 4 + 其余 4 门） | 15 | 13.2% |
| 路 2 已学 → 后继（离散数学 4 + 大学物理 2 + 线性代数 2 + 高等数学（下）2） | 10 | 8.8% |
| 路 3 下学期 → 预习（数据库原理 7 + 计算机组成原理 7 + 其余 4 门各 2） | 22 | 19.3% |
| 路 4 ItemCF 相似召回 | 49 | 43.0% |
| 路 5 热门兜底 | 18 | 15.8% |
| **合计** | **114** | 100% |

⚠️ 结构已经和旧版完全不同：**路 4（ItemCF 相似召回）成了最大来源，占 43.0%**。这有两层原因——一是数据底座从 116 个视频涨到 44,997 条资源，学生的真实学习记录终于撑得起协同过滤；二是每门课进候选池的条数被配额卡住（`RESOURCE_QUOTA_BY_KIND`：专业核心 8 / 学科基础 5 / 通识必修 2），把路 1「正在学同课程」从当年的七成压到 13.2%。

配额这一手很关键：不限制的话，《大学英语（三）》这类全校公共课靠播放量就能把专业核心课全挤出候选池。

## 3. 特征工程：8 维特征逐个拆解

这是整个推荐系统最核心的部分。**每个候选视频最终被表示成 8 个 0~1 之间的浮点数**，这 8 个数字就是排序模型看到的全部信息。

### 3.0 特征总表

特征名定义在 `train_model.py:292-301`：

```python
"feature_names": [
    "log_popularity",           # 0 热度
    "rating",                   # 1 评分
    "free_access",              # 2 是否免费
    "curriculum_graph",         # 3 课程图谱位置
    "itemcf_similarity",        # 4 协同相似度
    "platform_preference",      # 5 平台偏好
    "course_downstream_value",  # 6 后继课程价值
    "major_alignment",          # 7 专业匹配度
],
```

| # | 特征 | 一句话含义 | 数据来源 |
|---|---|---|---|
| 0 | `log_popularity` | 这视频有多火 | `video.popularity` |
| 1 | `rating` | 评分高不高 | `video.rating` |
| 2 | `free_access` | 是不是免费 | `video.is_paid` |
| 3 | `curriculum_graph` | 在课程图谱上的位置好不好 | `course` + `learning_record` |
| 4 | `itemcf_similarity` | 和你看过的视频有多像 | `learning_record` + 模型里的相似表 |
| 5 | `platform_preference` | 你平时爱去哪个平台 | `behavior_log` + `video.platform` |
| 6 | `course_downstream_value` | 这门课是几门课的基石 | `course.prerequisites` |
| 7 | `major_alignment` | 专业对不对口 | `video.major` / `course.major` / 文本 |

生产环境实现：`recommender.py:129-179` 的 `feature_vector()`
训练环境实现：`train_model.py:105-156` 的 `feature_vector()`

**两个同名函数，顺序必须严格一致**，否则权重会和特征错位。这是推荐系统里最容易出事故的地方之一。

---

### 3.1 特征 0：`log_popularity`（热度）

**计算**（`recommender.py:171`）：

```python
math.log1p(video["popularity"]) / 14.0
```

**为什么取对数**：播放量分布极度长尾——最火的 48.3 万播放，最冷的可能几千。直接除以最大值会让绝大多数视频挤在 0 附近，模型学不动。`log1p`（即 `log(1+x)`，专门处理 x=0 的情况）把长尾压缩成近似线性。

**为什么除以 14**：`log1p(483000) ≈ 13.09`，除以 14 刚好把最大值压到 1 以内，完成归一化。

**数据来源**：`video.popularity` 字段，建表在 `data_acquisition.py`，值来自 `data/raw/` 下的采集数据或种子数据。

**实测**：均值 0.7960，标准差 0.1975 —— 分布合理，说明对数压缩起作用了。

---

### 3.2 特征 1：`rating`（评分）

**计算**（`recommender.py:172`）：

```python
float(video["rating"]) / 5.0
```

5 分制直接除以 5 归一化。数据来源是 `video.rating`（如 4.8、4.9）。

**实测**：均值 0.8938，标准差 0.0562。**标准差极小**说明所有视频评分都在 4.4~4.9 之间挤着，区分度很弱。

**训练出的权重是 -0.05，近乎为 0 且略负**。这符合直觉：当所有候选评分都差不多时，这个特征提供不了信息，模型自然学不到有效权重。

> 教学点：**特征不是越多越好，方差太小的特征等于噪声**。

---

### 3.3 特征 2：`free_access`（免费可及性）

**计算**（`recommender.py:173`）：

```python
1.0 - float(video["is_paid"]) * 0.22
```

免费（`is_paid=0`）得 1.0，付费（`is_paid=1`）得 0.78。**付费不是完全排除，只是降权 22%**——因为付费课往往质量更高，一刀切掉会损失好内容。

**实测**：均值 **1.0000**，标准差 **1.0000**。

标准差恰好是 1.0 是代码里的兜底（`train_model.py:173` 的 `math.sqrt(var) or 1.0`）——真实方差是 **0**，也就是**所有训练样本的候选视频全是免费的**。

后果：特征恒为常数 → 标准化后恒为 0 → **权重训练出来正好是 0.0000**，这个特征在**模型内部**完全失效。

> 教学点：这是典型的"**特征坍缩**"。数据本身没有区分度时，再精巧的公式也救不回来。
>
> 不过它在**混合打分阶段**又被救回来了——见 [5.1 节](#51-混合打分模型分--规则分--质量分) 的 `0.06 * features[2]`。模型学不动的东西，可以用规则手工补上。

---

### 3.4 特征 3：`curriculum_graph`（课程图谱位置）

**这个特征在训练侧和推理侧各有一份实现，两边共用同一套分档。**

**训练时**（`train_model.py:229-239` 的 `curriculum_graph_score()`）：

```python
def curriculum_graph_score(state, course):
    """课程图谱特征，与 recommender.graph_score 用同一套分档。"""
    course_id = course["course_id"]
    if course_id in state["current_courses"]:
        return 1.0                                      # 正在学这门课
    prereqs = [p.strip() for p in (course.get("prerequisites") or "").split(",") if p.strip()]
    if any(prereq in state["completed_courses"] for prereq in prereqs):
        return 0.82                                     # 先修课已学完 → 后继课
    if course_id in state["next_courses"]:
        return 0.66                                     # 下学期要学
    return 0.4                                          # 其他
```

这三个课程集合由 `FeatureCache.student_state()` 算一次并缓存起来（`train_model.py:169-212`）：

```python
# 与召回口径一致：按「学生自己的专业 + 学期」判断，
# 而不是全库 course.status（那样所有学生共用同一份"正在学"集合）
"current_courses": {c["course_id"] for c in courses.values()
                    if c.get("major") == major and c.get("semester") == term},
"next_courses":    {c["course_id"] for c in courses.values()
                    if c.get("major") == major and c.get("semester") == term + 1},
"completed_courses": completed,   # 来自 learning_record 里 status='completed' 的视频所属课程
```

**为什么要缓存**：这三样东西只跟学生有关、跟候选视频无关。不缓存的话，每造一个样本都要遍历一遍课程表和 `learning_record`——4.5 万条视频跑两遍（训练 + 预测）就是十几万次重复扫描。生产版的注释写得很直白：「原实现里每造一个样本就要查 4 次数据库，样本一多训练时间就被数据库往返拖死」。

**推理时**（`recommender.py:157-168`）——靠**推荐理由文本**反推：

```python
reason = reasons.get(video["video_id"], "")
graph_score = (
    1.0  if "正在学习" in reason
    else 0.82 if "后继" in reason
    else 0.78 if "专业方向" in reason
    else 0.66 if "下学期" in reason
    else 0.4
)
```

**两侧分档对照**：

| 情况 | 训练侧 | 推理侧 |
|---|---|---|
| 正在学的课 | 1.0 | 1.0 |
| 先修已满足（后继课） | 0.82 | 0.82 |
| 专业方向召回 | —— | 0.78 |
| 下学期要学 | 0.66 | 0.66 |
| 其他（ItemCF/兜底） | **0.4** | **0.4** |

除"专业方向"这一档训练侧没有之外，两侧完全对齐。

而"其他情况"给 0.4 而不是 0，是因为线上没有"未命中"的候选——所有进入打分的候选都已经被某条规则捞出来了，只是理由不同；给 0.4 才是它的真实分布。

**这里曾经有一个训练/推理特征不一致（training-serving skew）**：早期版本训练侧未命中给 **0.0**、推理侧给 **0.4**，同一门课在两个阶段取值不同，模型学到的权重建立在错误的分布上。修法是把判断逻辑抽成 `curriculum_graph_score()` 一个函数、两侧共用同一套分档。详见第 9.1 节。

**权重解读**：实测权重 **-0.1268**（负值）。

> 这个负号很有意思：说明在当前数据下，**图谱位置越"正统"的视频，用户反而点击越少**。可能的原因——图谱召回的课是"应该学"的，但用户实际兴趣在别处；而且该特征与 `major_alignment` 存在共线性（专业匹配的课同时也是图谱命中的课），权重被抢走了。

### 3.5 特征 4：`itemcf_similarity`（协同相似度）

这是**唯一需要离线预计算**的特征，也是整个系统里算法含量最高的一环。

#### 第一步：文本向量化（TF-IDF）——建在课程级

`train_model.py:23-59`：

```python
def tokenize(text: str) -> List[str]:
    text = (text or "").lower()
    ascii_terms = re.findall(r"[a-z0-9+#.]+", text)      # 英文/数字保留（含 C++、C#、.NET）
    zh = re.findall(r"[\u4e00-\u9fff]", text)            # 中文逐字切
    bigrams = ["".join(pair) for pair in zip(zh, zh[1:])] # 中文相邻字组成二元组
    return ascii_terms + zh + bigrams
```

**中文分词的特殊处理**：项目没用 jieba 之类的分词库，而是用**字 + 二元组（bigram）**。比如"数据结构"会被切成 `数、据、结、构、数据、据结、结构`。这是中文文本处理的经典轻量方案——不需要词典，也能捕捉部分词序信息。

```python
def build_tfidf(videos, courses_by_id):
    docs = {}; df = Counter()
    for video in videos:
        course = courses_by_id[video["course_id"]]
        # 把 5 个字段拼成一篇"文档"
        text = " ".join([video["title"], video["tags"], video["summary"],
                         course["name"], course["concepts"]])
        counts = Counter(tokenize(text))
        docs[video["video_id"]] = counts
        for term in counts:
            df[term] += 1                                # 统计词出现在多少个文档里

    n_docs = len(videos)
    idf = {term: math.log((n_docs + 1) / (freq + 1)) + 1 for term, freq in df.items()}
    vectors = {}
    for video_id, counts in docs.items():
        raw = {term: (1 + math.log(count)) * idf[term] for term, count in counts.items()}
        norm = math.sqrt(sum(value * value for value in raw.values())) or 1.0
        vectors[video_id] = {term: round(value / norm, 6) for term, value in raw.items()}
    return {"idf": idf, "vectors": vectors}
```

**TF-IDF 公式拆解**：

| 部分 | 公式 | 含义 |
|---|---|---|
| TF（词频） | `1 + log(词在文档中出现次数)` | 出现越多越重要，用对数抑制高频词 |
| IDF（逆文档频率） | `log((N+1)/(df+1)) + 1` | 越少见的词越有区分度（"数据结构"比"课程"值钱） |
| TF-IDF | TF × IDF | 相乘得到词权重 |
| 归一化 | 除以 L2 范数 | 把向量长度变成 1，这样点积就等于余弦相似度 |

**数据来源**：`video.title`、`video.tags`、`video.summary`、`course.name`、`course.concepts` 五个字段拼接。

**实测**：词表大小 **3,412**，也就是 898 门课程合计产生了 3,412 个不同词条（TF-IDF 建在课程级，再把相似度按同课派生到视频，避免 44,997 条资源两两比较）。

#### 第二步：算视频两两相似度

`train_model.py:52-69`：

```python
def dot(a: Dict[str, float], b: Dict[str, float]) -> float:
    if len(a) > len(b):
        a, b = b, a              # 遍历更短的那个，省时间
    return sum(value * b.get(term, 0.0) for term, value in a.items())

def build_item_similarity(vectors):
    out = {}
    for video_id, vector in vectors.items():
        sims = []
        for other_id, other in vectors.items():
            if other_id == video_id:
                continue
            score = dot(vector, other)         # 向量已归一化 → 点积 = 余弦相似度
            if score > 0:
                sims.append({"video_id": other_id, "score": round(score, 6)})
        out[video_id] = sorted(sims, key=lambda item: item["score"], reverse=True)[:8]
    return out
```

**要点**：

- 向量已经 L2 归一化，所以**点积直接等于余弦相似度**，省掉除法
- 只保留分数 > 0 的（完全无共同词的直接丢弃）
- **每个视频只留 top8**，截断存储

**实测**：624 个有学习记录的物品 × 每个 top8 = 4,992 条相似边，存在模型 JSON 里。

#### 第三步：在线查特征

`recommender.py:140-144`：

```python
sim_score = 0.0
for watched in history:
    for item in model["item_similarity"].get(watched, []):
        if item["video_id"] == video["video_id"]:
            sim_score = max(sim_score, item["score"])
```

**取 max 而不是 sum**：只要和**任意一个**看过的视频很像就够了，不该因为看过很多不相关的视频而累加。这是"最大相似度"聚合策略。

**实测**：均值 0.0821，标准差 0.1415，**权重 0.5383（第二大）**。说明"和你已看的相似"是相当强的信号。

### 3.6 特征 5：`platform_preference`（平台偏好）

**计算**（`recommender.py:145-156`）：

```python
platform_rows = rows(con, """
    SELECT v.platform, COUNT(*) AS c
    FROM behavior_log b JOIN video v ON b.video_id=v.video_id
    WHERE b.student_id=? AND b.event_type IN ('play','complete','like','favorite')
    GROUP BY v.platform
""", (student["student_id"],))
total_platform = sum(row["c"] for row in platform_rows) or 1
```

**实测**：均值 **0.8571**，权重 **0.5279**。

均值 0.8571 说明行为高度集中在某一个平台——大概率是学生主要在 B站 看课，所以只要推荐 B站 视频这个特征就接近 1。

### 3.7 特征 6：`course_downstream_value`（后继课程价值）

### 3.8 特征 7：`major_alignment`（专业匹配度）

**计算**（`recommender.py:41-51`，训练侧同款在 `train_model.py:81-91`）：

```python
def major_alignment(student, video, course) -> float:
    video_major = (video.get("major") or "").strip()
    course_major = (course.get("major") or "").strip()
    if video_major:                                     # 视频标了专业
        return 1.0 if video_major == student["major"] else 0.0
    if course_major:                                    # 视频没标，看课程
        return 1.0 if course_major == student["major"] else 0.55
    text = " ".join([video.get("title") or "", video.get("tags") or "", course.get("name") or ""])
    if student["major"] in text:                        # 都没有，查文本
        return 0.9
    return 0.55                                         # 兜底
```

**四级降级策略**（这是本项目特征工程最细腻的地方）：

| 情况 | 返回值 | 逻辑 |
|---|---|---|
| 视频有专业标注，且匹配 | 1.0 | 最强证据 |
| 视频有专业标注，但不匹配 | **0.0** | 硬否决 |
| 视频无标注，课程有标注且匹配 | 1.0 | 次强证据 |
| 视频无标注，课程有标注但不匹配 | 0.55 | 软降权 |
| 都没有，但标题/tags/课程名里出现了专业名 | 0.9 | 文本兜底 |
| 什么都没匹配上 | 0.55 | 中性值 |

**为什么"视频标注不匹配"给 0.0 而"课程标注不匹配"给 0.55**：视频级标注是采集时精确打的，可信度高，不匹配就是明确错误；课程级标注比较粗（一门课可能跨专业），所以只做软降权。

**实测**：均值 0.3643，标准差 0.4430，权重 **1.3387 —— 全场最高**。

> **专业匹配度是整个模型里最重要的特征**，权重是第二名（ItemCF 0.5383）的 2.5 倍。
> 这符合业务直觉：学生最关心的就是"这课跟我专业有没有关系"。

## 4. 排序模型：轻量逻辑回归

### 4.1 标准化

`recommender.py:182-185`：

```python
def score(features: List[float], model: Dict[str, Any]) -> float:
    ranker = model["ranker"]
    x = [(features[i] - ranker["means"][i]) / ranker["stdevs"][i] for i in range(len(features))]
    return sigmoid(sum(ranker["weights"][i] * x[i] for i in range(len(x))) + ranker["bias"])
```

**Z-score 标准化**：`(x - 均值) / 标准差`，把每个特征拉成均值 0、标准差 1。

**为什么必须做**：`log_popularity` 在 0.5~0.95 之间波动，`itemcf_similarity` 在 0~0.3 之间波动。如果不标准化，梯度下降会在"数值大"的特征上走得太快、"数值小"的特征上几乎不动，收敛慢且不稳。

**均值和标准差存在模型里**（`ranker["means"]` / `ranker["stdevs"]`），推理时必须用**训练时**的这份，不能用线上数据重算——否则线上线下尺度不同，预测全错。

### 4.2 模型形式

```
z = Σ(weight_i × x_i) + bias
predicted_ctr = sigmoid(z) = 1 / (1 + e^(-z))
```

`sigmoid` 定义在 `:29-34`：

```python
def sigmoid(value: float) -> float:
    if value < -30:
        return 0.0          # 防止 math.exp 溢出
    if value > 30:
        return 1.0
    return 1 / (1 + math.exp(-value))
```

输出落在 (0, 1) 区间，可以解释为「点击概率」——这就是推荐里常说的 **pCTR（predicted Click-Through Rate）**。

那两个 ±30 的截断是工程防护：`math.exp(1000)` 会抛 `OverflowError`，超出就饱和到 0 或 1。

### 4.3 训练：批量梯度下降 + L2 正则

`train_model.py:167-191`：

```python
def train_logistic(samples: List[Tuple[List[float], int]]) -> Dict[str, Any]:
    dims = len(samples[0][0])
    # ① 先算每个维度的均值和标准差，用于标准化
    means = [sum(sample[0][i] for sample in samples) / len(samples) for i in range(dims)]
    stdevs = []
    for i in range(dims):
        var = sum((sample[0][i] - means[i]) ** 2 for sample in samples) / len(samples)
        stdevs.append(math.sqrt(var) or 1.0)      # 方差为 0 时兜底成 1，避免除零

    weights = [0.0 for _ in range(dims)]
    bias = 0.0
    lr = 0.18                                     # 学习率
    l2 = 0.015                                    # L2 正则系数

    for _ in range(480):                          # 迭代 480 轮
        grad_w = [0.0 for _ in range(dims)]
        grad_b = 0.0
        for features, label in samples:           # 遍历全部样本（批量梯度下降）
            x = [(features[i] - means[i]) / stdevs[i] for i in range(dims)]
            pred = sigmoid(sum(weights[i] * x[i] for i in range(dims)) + bias)
            err = pred - label                    # 预测 - 真实，交叉熵的梯度形式
            for i in range(dims):
                grad_w[i] += err * x[i] + l2 * weights[i]   # 数据梯度 + L2 惩罚
            grad_b += err
        scale = 1 / len(samples)
        weights = [weights[i] - lr * grad_w[i] * scale for i in range(dims)]
        bias -= lr * grad_b * scale
    return {"weights": weights, "bias": bias, "means": means, "stdevs": stdevs}
```

**逐点解释**：

| 参数 | 值 | 作用 |
|---|---|---|
| `lr`（学习率） | 0.18 | 每步走多远。太大震荡，太小收敛慢 |
| `l2`（正则） | 0.015 | 惩罚大权重，防止过拟合。加在梯度里的 `l2 * weights[i]` 就是它的导数 |
| 迭代轮数 | 480 | 全量跑 480 遍。样本只有 175 条，所以直接批量梯度下降足够快 |
| `err = pred - label` | —— | 逻辑回归 + 交叉熵损失时，梯度恰好化简成这个形式 |
| `scale = 1/len(samples)` | —— | 把累加的梯度变成平均值 |

**为什么不用 sklearn**：整个项目**零机器学习依赖**，`requirements.txt` 只有 fastapi / uvicorn / pydantic / requests。核心算法全部手写，好处是每一步都可解释、能在答辩时讲清楚，也避免了额外的环境安装风险。

## 5. 混合打分与 MMR 重排

### 5.1 混合打分：模型分 + 规则分 + 质量分

模型输出的 pCTR 不是唯一依据，最终混合分还要加上另外三项（`recommender.py:283-289`）：

```python
predicted_ctr = score(features, model)
blended_score = (
    0.62 * predicted_ctr              # 模型预测的点击概率
    + 0.2 * recall_strength(reason)   # 这条召回路本身有多可信
    + 0.12 * freshness_bonus(video)   # 视频本身的质量
    + 0.06 * features[2]              # 免费可及性（features[2] = free_access）
)
```

**四项权重之和恰好是 1.00**（0.62 + 0.20 + 0.12 + 0.06），这是一个完整的加权方案。

| 项 | 权重 | 来源 |
|---|---|---|
| `predicted_ctr` | 0.62 | 逻辑回归模型 |
| `recall_strength(reason)` | 0.20 | 按召回路径给的先验分 |
| `freshness_bonus(video)` | 0.12 | 热度 + 评分的加权 |
| `features[2]` | 0.06 | 免费可及性，直接复用第 2 维特征 |

> **一个精妙的设计**：`free_access` 在逻辑回归里学到的权重是 0（见 3.3 节），看起来完全失效了。但这里它通过 `0.06 * features[2]` 又以规则的形式回来了——免费视频（值 1.0）比付费视频（值 0.78）多得 `0.06 × 0.22 ≈ 0.013` 分。
>
> 这说明工程上的"特征失效"不等于"信息失效"：**当模型学不动某个特征时，可以用业务规则手工兜底**。这种"模型 + 规则"的双轨设计，是推荐系统里很常见的稳健性手段。


`recall_strength`（`:188-199`）按召回路径给分：

```python
def recall_strength(reason: str) -> float:
    if "正在学习" in reason: return 1.0     # 正在学的课，需求最急
    if "后继" in reason:     return 0.86    # 学完基础可以进阶
    if "专业方向" in reason: return 0.78    # 专业对口
    if "下学期" in reason:   return 0.74    # 预习
    if "ItemCF" in reason:   return 0.68    # 相似召回，信号较弱
    return 0.52                             # 兜底
```

`freshness_bonus`（`:202-207`）：

```python
def freshness_bonus(video: Dict[str, Any]) -> float:
    popularity = math.log1p(video["popularity"]) / 14.0
    rating = float(video["rating"]) / 5.0
    return min(1.0, 0.58 * popularity + 0.42 * rating)
```

**为什么要混合而不是纯靠模型**：模型只有 175 个训练样本，容易对某些召回路过度自信。规则分提供了一个"业务先验"兜底——即使模型说 ItemCF 的候选好，也不会让"正在学的课"排到后面去。

> 注意 `recall_strength` 是靠**匹配 reason 字符串**判断的。所以第 2 节讲的 `setdefault` 先到先得，会直接影响这里的分数——理由文本被谁先写上，就决定了走哪个分支。

### 5.2 MMR 重排：解决"一屏全是一样东西"

**问题**：第 2.6 节实测显示，114 个候选里《数据结构与算法》一门贡献了 7 条，下学期预习的《数据库原理》《计算机组成原理》也各有 7 条。配额虽然限制了单课条数（专业核心最多 8 条），但一屏 24 张卡里仍可能有 7~8 张来自同一门课，用户体验极差。

**MMR（Maximal Marginal Relevance）** 的核心思想：挑选时同时考虑**相关性**和**与已选内容的差异度**。

`recommender.py:220-240`：

```python
def mmr_rerank(items, model, limit):
    selected = []
    pool = items[:]
    platform_seen = defaultdict(int)
    while pool and len(selected) < limit:
        best_index = 0
        best_score = -1.0
        for index, item in enumerate(pool):
            # ① 与已选内容的最大相似度 = 冗余度
            redundancy = max(
                [similarity_between(model, item["video_id"], chosen["video_id"]) for chosen in selected] or [0.0]
            )
            # ② 同平台已出现次数 = 平台惩罚
            platform_penalty = 0.015 * platform_seen[item["platform"]]
            # ③ 综合打分
            rerank_score = 0.86 * item["score"] - 0.08 * redundancy - platform_penalty
            if rerank_score > best_score:
                best_index = index
                best_score = rerank_score
        chosen = pool.pop(best_index)
        chosen["rerank_score"] = round(best_score, 4)
        platform_seen[chosen["platform"]] += 1
        selected.append(chosen)
    return selected
```

**贪心逐条挑选**，每条都重新算一遍：

```
最终分 = 0.86 × 相关性  −  0.08 × 冗余度  −  0.015 × 该平台已选次数
```

| 项 | 系数 | 作用 |
|---|---|---|
| `0.86 * item["score"]` | 0.86 | 主要看相关性 |
| `- 0.08 * redundancy` | -0.08 | 和已选内容像 → 扣分 |
| `- 0.015 * platform_seen[platform]` | -0.015 | 同平台堆积 → 逐次加重惩罚 |

**冗余度怎么算**（`:210-217`）：

```python
def similarity_between(model, left, right) -> float:
    for item in model["item_similarity"].get(left, []):
        if item["video_id"] == right:
            return float(item["score"])
    for item in model["item_similarity"].get(right, []):
        if item["video_id"] == left:
            return float(item["score"])
    return 0.0
```

双向查表（因为 top8 截断可能导致单向缺失），查不到就是 0（不相似）。

**平台惩罚是累进的**：同一平台第 1 条扣 0.015，第 2 条扣 0.030，第 3 条扣 0.045……所以一个平台不太可能连出很多条。

> 教学点：MMR 是**用精度换多样性**的典型手段。调大 `redundancy` 系数会更"杂"，调小会更"专"。在 learn 演练场里，完整方案的多样性指标（0.333）明显高于其他模型，就是这一步的功劳。

## 7. 评估方法

### 7.1 留一法（Leave-One-Out）

定义在 `backend/evaluate_model.py`。核心思路：

```
对每个学生：
    取出他所有"弱正样本"（进度 ≥ 25% 的视频）
    对每一条：
        ① 把它从候选池里"藏起来"（但其他历史保留）
        ② 重新训练模型（用不包含这条的样本）
        ③ 让模型生成推荐
        ④ 看被藏起来的那条有没有进 top5 / top9
```

**关键实现**：`evaluate_model.py:86-91`

```python
recs = recommender.recommend_professional(
    student_id,
    "all",
    model_override=fold_model,
    exclude_video_ids=set(context_ids),   # 排除集合
    context_video_ids=set(context_ids),   # 上下文集合
)
```

这两个参数从外部注入，是为了**假装那条记录不存在**——不能真去删数据库（会污染线上数据），所以从参数传进去。这对应 `recommender.py:54-64` 里 `_touched_video_ids()` 的 `override` 分支。

**为什么叫"留一"**：每次留出一个样本当"答案"，其余用于构造候选池。

### 7.2 指标

| 指标 | 含义 | 本项目是否使用 |
|---|---|---|
| HitRate@5 | 前 5 条里命中至少一条就算成功 | ✅ 主指标 |
| HitRate@9 | 前 9 条里命中 | ✅ |
| Precision@5 | 前 5 条里命中几条 / 5 | 参考 |
| NDCG@5 | 命中项排得越靠前分越高 | 参考 |
| Coverage | 推荐覆盖了多少比例的物品池 | 参考 |
| Diversity | 推荐结果覆盖多少个不同平台 | 参考 |

### 7.3 实测评估结果

在 learn 教学系统里对 7 个模型做了横向对比，**P@5 呈现清晰的递进阶梯**：

| 模型 | 思路 | P@5 |
|---|---|---|
| L1 热度榜 | 只按播放量排序 | 0.00 |
| L2 评分榜 | 按评分 + 热度 | 0.00 |
| L3 课程图谱规则 | 本项目三条规则 | 0.20 |
| L4 TF-IDF 内容相似 | 文本向量余弦 | 0.40 |
| L5 ItemCF | 相似度表 | 0.40 |
| L6 逻辑回归 | 8 维特征 | 0.80 |
| L7 完整方案 | 召回 + LR + MMR | 0.80，且多样性翻倍 |

这就是"**为什么需要这么复杂的算法**"的最好证明——从 0 到 0.8 的跃升，每一步都有明确的贡献。

## 9. 已知问题与改进建议

### 9.1 特征不一致（中优先级）

**问题**：`curriculum_graph` 在训练时用 SQL 判断（未命中 = 0.0），推理时用推荐理由文本判断（未命中 = 0.4）。同一门课在不同阶段取值不同。

**影响**：模型权重建立在错误分布上。实测该特征权重为负（-0.1268），部分原因可能就是这个偏差。

**修复思路**：把训练侧的判断逻辑抽成一个函数，两边共用。理想做法是让 `professional_candidates` 返回结构化标签（如 `recall_type="studying"`）而不是拼中文句子，再由标签算分——这样也顺便解决了下面 9.2。

### 9.2 靠中文文本匹配判断召回类型（中优先级）

**问题**：`recall_strength()` 和 `graph_score` 靠 `if "正在学习" in reason` 这种字符串包含判断。推荐理由文案一旦改动（比如把"正在学习"改成"在学"），分数计算会静默失效。

**修复思路**：`reasons` 从 `Dict[str, str]` 改成 `Dict[str, Tuple[str, str]]`，第一个元素是类型枚举，第二个是展示文案。

### 9.3 `setdefault` 导致理由归属被抢先（低优先级）

**问题**：三条图谱规则按顺序执行，`reasons.setdefault` 先到先得。规则 1（正在学）会把数据结构的所有视频占掉，导致规则 2（学过后继）对同一批视频无法写入自己的理由。

**实测证据**：114 个候选里，"正在学习"15 条、"后继"10 条。"正在学"仍然占着优先级最高的位置，只是有了配额限制后不再一家独大。

**修复思路**：改成带优先级的写入（高优先级理由可覆盖低优先级），或允许一个视频挂多个理由标签。

### 9.4 `prerequisites LIKE` 模糊匹配隐患（低优先级）

**问题**：`LIKE '%C301%'` 会匹配到 `C3011`、`XC301` 这类 ID。

**当前影响**：无。课程 ID 都是 4 位（C101~C602），不会误伤。

**修复思路**：用 `',' || prerequisites || ',' LIKE '%,C301,%'` 精确匹配逗号边界，或把先修关系拆成独立的关联表。

### 9.5 训练样本量过小（需知晓）

**现状**：175 条样本、25 个正样本。

**影响**：AUC 0.9475 参考价值有限；模型对数据波动敏感；新增几十条日志就可能显著改变权重。

**建议**：在答辩材料中如实说明这是"小样本演示级模型"，并指出扩大样本后的优化方向。不要把它包装成工业级效果。

### 9.6 `free_access` 在模型内部失效（低优先级）

**问题**：所有训练样本的候选视频都是免费的，导致特征方差为 0，标准化后恒为 0，权重训练结果正好是 0.0000。这个特征在逻辑回归里占了一个维度，却没提供任何信息。

**缓解**：混合打分阶段用 `0.06 * features[2]` 手工补回了一点作用（见 5.1 节），所以业务上没出问题。

**修复思路**：让训练样本覆盖付费视频；或者干脆从特征向量里删掉它、只保留混合分那一项，省一个模型维度。

第 2 点容易被忽略但很关键：`train_fold_model()` 的返回值里塞了 `_context`，而它是**给评估流程在内存里用的**中间态，不是模型产物。`evaluate_model.py:122-131` 是现造一份 `base_bundle` 传进去的，并不从模型文件读 `_context`——所以剔除它没有任何副作用。保留的话，模型文件会从 960 KB 膨胀到 1252 KB（**多出 281 KB / +30%**），因为 `_context` 里装了一整份候选快照（视频 + 课程 + 相似度矩阵）。

**修复验证**：重跑后输出与修复前逐项相同；新写出的 `ranker_model.json` 与旧文件逐字段相同（`ranker`、`item_similarity`、`tfidf` 全部相等），推荐接口首条分数不变。**属于"让命令能跑通"，不改变任何模型效果。**（当时的样本数、AUC 与文件体积见本节上文，是旧数据规模下的测量值。）
